# Signal One Marketing Distribution Playbook

This document defines how Signal One should turn the public website into qualified security-company pipeline.

The website is the source of truth for public claims. Paid and organic marketing must not make a stronger claim than the current website and `docs/PUBLIC_CLAIMS_REGISTER.md`.

## 1. Commercial audience

Primary ICP:

- South African private security / guarding companies.
- Owners, directors and managing directors.
- Operations managers.
- Control-room managers.
- Regional / branch managers.
- Procurement, IT and compliance stakeholders when a deal progresses.

Secondary audiences:

- Security supervisors evaluating operational tooling.
- Technology / communications buyers looking for PoC, managed devices and connectivity.
- Existing security companies expanding from software into connected field communications.

Recruitment audiences must remain separate from buyer campaigns.

## 2. Core category position

Primary category phrase:

**Security operations software for South African guarding companies.**

Primary promise:

**Control every site. Know what happened. Prove the service.**

Supporting operating position:

**One operational record from guard to control room to client.**

Connected-operations extension:

**Add push-to-talk communications, managed devices and connectivity when the operation needs them.**

Do not lead campaigns with the entire Signal One catalogue. Lead with the security operating problem, then expand into connected operations.

## 3. Funnel

### Awareness / problem recognition

Goal: create a reason to reconsider the current operating model.

Content:
- security contracts failing quietly;
- control-room exception management;
- digital occurrence records;
- client proof and service evidence;
- attendance vs scheduled staffing;
- patrol evidence vs manual confirmation.

Destination:
- `/insights/*`
- relevant `/solutions/security/*` page

Primary metric:
- qualified engaged sessions;
- insight-to-product click rate.

### Evaluation

Goal: let the buyer understand Signal One without needing a sales call.

Destination:
- `/tour`
- `/pricing`
- `/trust`
- `/solutions/security`

Primary metric:
- tour view rate;
- pricing view rate;
- trust-page view rate;
- return visits by campaign / account where available.

### Intent

Goal: convert the buyer into a clear commercial conversation.

Destination:
- `/contact?intent=demo`
- `/contact?intent=pricing`
- `/contact?intent=pilot`
- `/contact?intent=trust`

Primary metric:
- enquiry start rate;
- enquiry completion rate;
- qualified opportunity rate.

### Commercial

Goal: move from enquiry to pilot / proposal / live customer.

This stage belongs in Sales OS / CRM, not website analytics alone.

Primary metric:
- marketing-qualified opportunity;
- sales-qualified opportunity;
- proposal rate;
- pilot rate;
- win rate;
- pipeline and revenue by source / campaign.

## 4. Channel priority

### Priority 1 — Google Search

Use for high-intent demand already looking for a solution.

Start with tightly grouped campaigns around:
- security guard management software South Africa;
- guard patrol software;
- security guard attendance system;
- electronic occurrence book security;
- security control room software;
- security client reporting / proof of service;
- push-to-talk for security companies.

Each ad group should land on the matching `/solutions/security/*` page, not the homepage.

Do not buy broad generic terms until conversion data proves the high-intent pages work.

### Priority 2 — Founder / executive LinkedIn

Purpose: create category authority and open account-level conversations.

Weekly source content:
- one substantial Signal One insight;
- one operating diagram / visual;
- one product-proof post;
- one practical buyer question or contrarian point of view.

Founder posts should sound like an operator explaining a problem, not corporate advertising.

Every insight should be repurposed into:
1. long-form article;
2. founder post;
3. company-page post;
4. short visual carousel / diagram;
5. sales follow-up asset;
6. email / WhatsApp follow-up link where appropriate.

### Priority 3 — Company LinkedIn

Use for:
- product proof;
- deployment progress;
- new search / insight content;
- verified customer evidence;
- event / webinar promotion;
- device and connected-operations education.

The company page supports credibility; founder / operator distribution should do more of the demand creation.

### Priority 4 — Retargeting

Only after sufficient website traffic exists and privacy / consent requirements are reviewed.

Retarget:
- product-tour viewers;
- pricing viewers;
- trust-page viewers;
- high-intent workflow-page visitors;
- visitors who started but did not submit an enquiry, where permitted.

Do not use retargeting to compensate for weak landing-page conversion.

### Priority 5 — Industry distribution

Use:
- security-industry events;
- associations;
- technology partners;
- webinars;
- supplier / distributor relationships;
- existing industry networks.

The best live demonstration is the full operating chain:

**guard action → operational state → control-room exception → management / client proof**

Do not run a hardware-only stand if the commercial goal is Guard adoption.

## 5. Campaign naming

Format:

`channel_market_audience_problem_offer_yyyymm`

Examples:

- `google_za_securitycompany_patrol_demo_202610`
- `google_za_securitycompany_controlroom_tour_202610`
- `linkedin_za_director_contractrisk_insight_202610`
- `linkedin_za_opsmanager_occurrence_tour_202610`

Keep names lowercase and use underscores.

## 8. Weekly publishing rhythm

Minimum viable rhythm:

### Monday
Publish or refresh one core insight.

### Tuesday
Founder LinkedIn post derived from the insight.

### Wednesday
Product-proof post showing one screen / workflow with synthetic or authorised data.

### Thursday
Buyer-question post:
- a problem;
- a short explanation;
- link to the relevant high-intent page.

### Friday
Sales enablement:
- send the strongest content from the week to active opportunities where relevant;
- update objections / questions heard by sales;
- feed those questions back into future website FAQ and insight content.

Quality is more important than daily volume.

## 9. Paid-search launch sequence

Do not launch all keywords at once.

### Wave 1

- guard management software;
- guard patrol software;
- security guard attendance;
- security control room software.

### Wave 2

Add only after Wave 1 produces qualified enquiries:

- electronic occurrence book;
- client reporting / proof of service;
- push-to-talk security.

### Wave 3

Expand into competitor / alternative / broader category searches only once conversion and qualification data is stable.

## 10. Experiment design

Change one major variable per test.

Recommended first tests:

1. Product tour vs Book demo as the primary search landing CTA.
2. "Control every site" vs problem-specific headline on paid search.
3. Pricing package page shown before demo vs after demo.
4. Client-proof message vs control-room message for owner / director audiences.

Minimum result to care about:
- qualified opportunities, not CTR alone.

## 11. Reporting

Weekly dashboard:

| Funnel stage | Metric |
| --- | --- |
| Demand | Sessions by source / campaign / landing page |
| Engagement | Tour, pricing, trust and insight progression |
| Intent | Form starts and successful submissions |
| Qualification | Qualified opportunities by source |
| Commercial | Proposals, pilots and wins by source |
| Efficiency | Cost per qualified opportunity and cost per won customer |

Avoid optimising to:
- impressions;
- follower count;
- raw form volume;
- click-through rate without qualification.

## 12. Sales OS handoff

The website already forwards campaign and intent fields through the intake payload.

Sales OS / CRM should store at minimum:

- original source;
- original medium;
- original campaign;
- original landing page;
- latest high-intent page;
- buyer intent;
- configured quote if applicable;
- opportunity stage;
- qualified / disqualified reason;
- pipeline value;
- won revenue.

Do not overwrite original attribution when a lead returns through another channel.

## 13. Proof flywheel

Every pilot should create:

1. baseline operating problem;
2. deployment scope;
3. measurable before / after evidence;
4. customer-approved quote;
5. claim register entry;
6. case study;
7. LinkedIn story;
8. sales collateral;
9. retargeting / paid proof creative.

Use `docs/CASE_STUDY_EVIDENCE_TEMPLATE.md`.

## 14. Launch gate

Before spending materially on paid traffic:

- [ ] SIGNAL_ONE_ANALYTICS_URL is configured and tested.
- [ ] Intake endpoint is receiving attribution fields.
- [ ] Sales OS / CRM preserves original attribution.
- [ ] Product tour works on mobile and desktop.
- [ ] Demo / pricing forms are monitored.
- [ ] At least one person owns response SLA for inbound leads.
- [ ] Paid landing pages have no unverified public claims.
- [ ] Search campaign conversion is tied to qualified opportunity, not only form submission.
