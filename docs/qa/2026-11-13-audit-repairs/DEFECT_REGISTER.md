### Root causes established in Phase 2

- **D-001 / D-002.** The marketing material contract in `app/marketing-system.css` repaints every `<main>` dark but re-tokened text only for surfaces nested inside `<main>`. `LegalPage` puts `surface-light` on `<main>` itself, so its `text-text-2` body copy kept the light-surface slate on the dark gradient. Fixed by extending the contract to text directly inside a light-surface `<main>`.
- **D-003.** The Menu toggle is hidden at `xl` (1280 px) but the sheet it opens was hidden at `lg` (1024 px): `app/components/Header.tsx:193` `lg:hidden` -> `xl:hidden`.
- **D-013 (React #418).** `SceneTransition` rendered `<div class="s1-scene-route">{children}</div>`. `children` is the layout router element, and it reaches the client as a *lazy* element whenever the chunk holding the route error boundary (`app/(marketing)/error.tsx`, passed as the router's `error` prop) has not finished loading. When that lazy element suspends as a direct child of a host element during hydration and resolves within the same tick, React replays the host element (`replayBeginWork`, `case 5`), which calls `beginWork` on the `<div>` again without rewinding the hydration cursor. The cursor has already moved to the div's first child (`<main>`), the tag does not match, and React throws #418 and client-renders the root. Recorded component stack: `div <- SceneTransition <- body <- html <- root layout`. Reproduced on demand by delaying that one chunk: 20 of 96 loads failed before the fix, 0 of 144 after (`data/hydration-diag-error-chunk-delay-before.json`, `-after.json`). Fix: a passthrough component between the `<div>` and `children`, so the suspension is replayed in a function component, which does not touch the cursor. Proof: 684 cold loads (all routes, three viewports) with 0 errors on the fixed build and 456 more on the final build (`logs/10-hydration-prod-after.log`, `logs/31-hydration-final.log`); the diagnostic build before the fix logged 5 in 570 (`logs/06-hydration-prod-diag-before.log`).
- **D-014.** `tests/e2e/helpers.ts` clicked radios and checkboxes with `force: true`, which skips Playwright's hit-target check. After a step change the page is still scrolling (heading focus plus `scroll-behavior: smooth`); in failing runs the first checkbox of the "start" step sat at y = 34 to 54 px, under the 76 px fixed header, and the forced click landed on the header navigation (in one trace on the "1Service" link, which navigated to /service). The control was never toggled, so `helpers.ts:53` failed. Evidence: trace in `data/d014-before/`, click log in `data/d014-instrumented-before.jsonl` (target `NAV`, `inHeader: true`, six times at the same point). The product already keeps focused controls clear of the header (`scroll-margin-top: 96px`, `app/globals.css:1817`), and a real click works. The helper now uses real clicks; no assertion and no retry loop changed. Before: 4 of 16 and 2 of 6 failed; after: 30 of 30 passed (`logs/11-d014-repro-before.log`, `logs/14-d014-after-30x.log`).
- **D-015.** The Connect interest allowlist was renamed deliberately in commit `ead909f` (2026-10-30); the fixture in `tests/connect/exchange.test.mjs` (from `d7f844f`) still sent the old value. The fixture was updated, the allowlist was not loosened.
- **D-009.** With `object-fit: cover` in a box taller than the source's shape, the browser decodes by height, but the `sizes` hints gave the box width or a narrower breakpoint value. No source file is too small.
