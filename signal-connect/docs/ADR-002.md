# ADR-002 — First-party QR encoding and independent validation

**Status:** Executed 02B / preview-only; not a production QR approval
**Date:** 2026-10-23
**Input specification:** `docs/SIGNAL_CONNECT_V3_EXPERIENCE_ARCHITECTURE.md`; `docs/SIGNAL_CONNECT_V3_SURGICAL_EXECUTION_PLAN.md`

## Library provenance
- **Project:** Nayuki QR Code generator library, TypeScript port, official source `typescript-javascript/qrcodegen.ts`
- **Upstream:** https://github.com/nayuki/QR-Code-generator
- **Pinned commit:** `3c6d0b3cefb4e049dc337e82237c9644399716a8`
- **Licence:** MIT — upstream copyright and entire licence header preserved inside `lib/vendor/qrcodegen.ts`.
- **Local modification:** one trailing ESM export `export { qrcodegen };`; no QR encoding logic or mathematical constants modified.
- **Why vendored:** standalone audited encoder, no runtime network/API dependency, no new `npm` production package, fully source-controlled provenance.

## Trust boundary
The single canonical URL resolver `lib/links.ts` accepts only `CONNECT_PUBLIC_ORIGIN` and the known typed founder ID. It currently accepts only the verified **preview** origin:
`https://signal-connect-v3-source-preview.vercel.app`
No request `Host` header, query string or client supplied data is used to build a code. QR is never generated for unknown people. If env is missing or origin not approved: `/qr/[profile]` returns 503, and presenter displays an honest non-scannable configuration message.

## Output
- Same-origin `GET /qr/andisiwe`, SVG `image/svg+xml`, closed-by-default Content Security Policy.
- Nayuki `QrCode.encodeText(..., Ecc.MEDIUM)`, full four-module white quiet zone, 1×1 black modules on white background.
- No logo cutout, blur, animation, external service or client-side QR generation.
- Server-rendered presenter `QRDisplay` is visible at first render, not behind a loading spinner.
- Code is **PREVIEW ONLY — NOT FOR PRINTING OR NFC PROVISIONING**. Stable final Signal One URL is a separate approval gate.

## Tests
- Existing origin resolver tests reject untrusted, malformed and presenter paths.
- Browser requests validate 200 SVG, 404 for unknown founder, correct first-party image URL, white base and no console errors.
- The GitHub Actions job installs **ZBar** (`zbarimg`), decodes the exact captured `test-results/qr-andisiwe.png` screenshot independently of the Nayuki library, then byte-compares the result with the allowlisted preview visitor URL.
- Mobile physical scan on real iPhone/Android is STILL REQUIRED before external rollout. ZBar/Chromium evidence is not a real-device signoff.
- Background PWA shell/remote origin QR caching is out of this mission: the code only works offline if its image was previously cached; follow up in 02C to assess offline behavior.

## Constraints
No V2 edits, no lead endpoint, no external QR image API, no Wallet, no printed-code commitment, and no claims of production readiness from preview CI.
